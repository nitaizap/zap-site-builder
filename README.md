# בונה האתרים של זאפ

מבריף של לקוח לאתר חי: WordPress + Elementor בעברית, מוכן ל-SEO, עם בדיקות במדידה. האתר נדחף ישירות לשרת הלקוח דרך **Novamira** (אפשר לערוך הכול ב-Elementor), או נארז כ-zip מוכן להעלאה.
רץ ב-Claude Code בענן (claude.ai/code), כמה אתרים במקביל, בלי שום התקנה אצלכם במחשב.

## שימוש — כל אתר

1. נכנסים ל-**claude.ai/code**, בוחרים את הריפו `zap-site-builder` ואת הסביבה **zap-sites**.
2. כותבים `/zap-site` ומדביקים את הבריף (טקסט, קבצים, לוגו, תמונות, קישור לאתר הישן). זה הכול.
3. Claude חוקר את העסק, שואל **הודעה אחת** עם מה שחסר, ובונה.
4. **עצירה אחת:** מקבלים קישור לתצוגה של 3 כיווני עיצוב (מחשב + נייד) ואת עץ האתר עם מילות המפתח.
   עונים באות (A/B/C) ומאשרים את העמודים. רוצים בלי עצירות? כותבים "בלי עצירות".
5. **מסירה:** אם לאתר הלקוח יש Novamira (שרתי ה-staging של זאפ, `*.ussl.co.il`): Claude דוחף אליו את האתר
   (גיבוי → קוד → תוכן, נעילת staging: בלי מיילים ללקוח, noindex), מריץ QA על האתר החי ומצלם אותו.
   בחיבור הראשון לאתר מקבלים קישור + קוד קצר — מנהל באתר מאשר פעם אחת. בלי Novamira: zip + צ'קליסט עלייה.
6. בסוף מקבלים: קישור לאתר, קישור לעורך Elementor, מספרי QA, `BRIEF-CHECK.md` (כל שורה בבריף מול האתר) והחוסמים לעלייה.

**כמה אתרים במקביל:** פותחים סשן חדש לכל לקוח (ואפשר כמה אנשים במקביל). כל אתר עובד בענף משלו
(`site/<slug>`) ובאתר יעד משלו, ולא מתנגש באחרים. כלל אחד: לקוח אחד לסשן.

**המחשב כבוי?** הסשן רץ בענן של Claude, לא אצלכם. אפשר לסגור את הדפדפן ולחזור (גם מהנייד) — העבודה ממשיכה
ונשמרת בענף. מה שעוצר אותה: שאלה או אישור שמחכים לכם (הודעת ההשלמות של ההתחלה, בחירת כיוון, אישור ראשון
לחיבור Novamira, ובמצבי הרשאה מסוימים — אישור לפקודת הדחיפה). כדי לרוץ עד הסוף: לכתוב "בלי עצירות" ולהגדיר
מראש את `ZS_NOVAMIRA` (למטה).

**תיקונים מהלקוח:** באותו סשן (או חדש: "תמשיך את האתר <slug>"), שולחים את כל ההערות בהודעה אחת.
Claude מעדכן, בונה, בודק ואורז מחדש.

## מה יש בתוך ה-zip

- `public_html/` — אתר וורדפרס מלא (ליבה, תבנית, תוספים, תמונות)
- `database.sql` — כל הכתובות כבר מכוונות לדומיין של הלקוח
- `deploy.sh` — התקנה בפקודה אחת על השרת (CloudPanel / כל שרת עם wp-cli)
- `DEPLOY.md`, `LAUNCH-CHECKLIST.md`, `QA-REPORT.md`

## הגדרה חד-פעמית (מנהל)

1. claude.ai/code → סביבות → **סביבה חדשה** בשם `zap-sites`:
   - **Network access: Full** (צריך wordpress.org)
   - **Setup script:** `bash bin/setup-cloud.sh`
   - משתני סביבה (לא חובה): `OPENAI_API_KEY` לתמונות AI · `ZS_SHAREPOINT_FLOW_URL` לשמירה ב-SharePoint
   - **`ZS_NOVAMIRA`** (מומלץ מאוד): `zap-builder:<application password>` של משתמש אינטגרציה באתר הבסיס של זאפ.
     כל אתר שמשוכפל מהבסיס יורש אותו, ואז אין קוד אישור לכל אתר וגם סשן חדש מתחבר לבד
     (פירוט: `.claude/skills/zap-site/references/novamira.md`).
2. לוודא שאפליקציית Claude ב-GitHub מותקנת עם גישה לריפו.
3. בדיקה: בסשן חדש להריץ `bin/zs doctor` — כל השורות OK.

## הרשאות לצוות — מי יכול להריץ את זה

כל מי שיש לו: (1) גישה לריפו `nitaizap/zap-site-builder` ב-GitHub (collaborator או צוות בארגון),
(2) Claude Code בענן (claude.ai/code) עם אפליקציית GitHub מחוברת, (3) גישה לסביבה `zap-sites` —
פותח סשן על הריפו וכותב `/zap-site`. הסקיל, המנוע והתבנית כולם בתוך הריפו, אז כולם עובדים עם אותה גרסה.
לתמונות AI ולמחקר מילות מפתח צריך את החיבורים (Weave / Ahrefs) בחשבון של מי שמריץ. אישור Novamira הראשון
לכל אתר דורש מנהל באותו אתר — אלא אם הוגדר `ZS_NOVAMIRA`.

## איך זה בנוי (בקצרה)

Claude כותב את התוכן וההחלטות לקובץ אחד, `sites/<slug>/site.json`. מנוע (`bin/zs`) הופך אותו לאתר אמיתי:
ספריית סקשנים מעוצבת ובדוקה → עמודי Elementor שאפשר לערוך, תבנית אחידה עם הדר/פוטר/טופס לידים,
Yoast, סכמה, נגישות ותקני זאפ. לפני הבנייה יש **ולידציה** (מילת מפתח לכל עמוד, אין דירוגים מומצאים,
טלפון שמחייג למספר המוצג...), ואחריה **QA במדידה** על כל עמוד במחשב ובנייד. אריזה נחסמת כל עוד יש שגיאות.
